DBacklog（3 项）

B1 · base-sync 会话起点门
模式：用户的期望锚定在远端 main + 线上生产的并集上，代理在 worktree 子集上工作——漂移穿过所有现有门（分支卫生、liveness 发布校验），用户成了那个回归测试（「你需要先拉取下远端 main」×多次；「先 pull 下远端代码，然后分析看看」已成开场白）。命中：v0.12.41 差点带着缺失计费运营 UI 的基线上线。机制建议：个人 hooks/包装脚本在会话起点自动 git fetch + 报告 behind/ahead，并在回答 go-live 类问题前先查线上运行版本。等 hook 基建成型后落地，比技能文更可靠。
B2 · 发布仪式的半自动化
模式：「提交推送，并打一个新 tag」11 月出现约 15 次，变体仅「不打新 tag」（配置同步类）。机制建议：seekstation 仓库加一个 /release 项目技能或 git alias（提交推送 → tag → 触发 CI → 报告流水线链接），把固定三连压成一条命令。属项目级改造，不在本仓库。
B3 · 通道故障升级超时
模式：验证通道故障 2 小时未升级为用户问题（RiloPlayer UI 自动化）。A8 已在 apple-design 落一条规则；机制化版本（监控自动化服务健康、超时自动升级）需要 harness hook，记入 devex 待办。与 [[careful/reflect]] 原则 encode-lessons-in-structure 一致。
